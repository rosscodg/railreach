# Depositing the dataset

`zenodo.json` and `README.md` in this directory are **generated by
`_build/generate-pages.py`**. Do not edit them by hand — rebuild instead, so
every count and date in them matches the dataset it describes.

Both platforms below need an account and acceptance of their terms, so the
upload is a person's job. Everything up to that point is done.

---

## 1. Zenodo — the one worth doing first

Gets the dataset a DOI, which is a permanent identifier that survives the site
moving or going away. It also puts a record into DataCite and OpenAIRE, which
is the layer academic search and citation tools read.

1. Sign in at <https://zenodo.org> (ORCID or GitHub works).
2. **New upload** → drag in these three files:
   - `data/journey-times.csv`
   - `data/journey-times.json`
   - `_build/deposit/README.md`
3. Fill the form from `zenodo.json`. The field names match:
   title, description, creators, licence (CC BY 4.0), version, keywords,
   related identifiers, notes. Access right is **Open**.
4. Publish. The DOI appears immediately.

**After publishing**, feed the DOI back into the site — it belongs in the
`Dataset` JSON-LD as `identifier`, and in the citation line on `/about/`. Both
are generated, so it is a one-line change in `generate-pages.py`. Ask and it
gets wired in.

Reserving a DOI before publishing is possible if you want it to appear in the
files themselves, but it makes the deposit un-editable in ways that are
awkward on a first run. Simpler to publish, then wire the DOI back.

### Versioning

Zenodo handles new versions properly: each release gets its own DOI and a
concept DOI resolves to the latest. When the dataset is next reviewed, use
**New version** on the existing record rather than creating a new upload, so
the citation history stays connected.

## 2. Hugging Face — for the ML data ecosystem

Heavily crawled, and the place people look for training and evaluation data.

1. Sign in at <https://huggingface.co>, then **New dataset**.
2. Name it something stable, e.g. `railreach/uk-london-journey-times`.
3. Upload `data/journey-times.csv` renamed to `journey-times.csv` — the YAML
   front matter in `README.md` points at that filename.
4. Upload `_build/deposit/README.md` as the dataset card. The front matter
   configures the licence, tags and the CSV split; the body is the card.

If you rename the CSV, change `data_files.path` in the generator's card
template to match, or the dataset viewer will not load.

---

## 3. Kaggle — optional

Lower value than the two above and more manual, but it reaches a different
audience. Same three files, same description. There is no metadata file to
generate for it; copy from `README.md`.

---

## What not to do

**Do not add RailReach as a citation on Wikipedia.** It is against their
conflict-of-interest guidelines, and a self-added citation that gets reverted
is more visible than no citation at all. If the data is good enough to be
cited there, someone else will do it.
